# Subtasks Checklist Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add, rename, tick, delete and reorder a task's subtasks as a checklist in the card detail, as real Google subtasks that sync offline, and show a done/total count on board cards.

**Architecture:** Steps are Google subtasks. Adding reuses the queued `create` op with a `parent`. Reordering is a new queued `reorder` op that replay sends as Google's `tasks.move` with `parent` and `previous`. While changes wait, the app renumbers sibling positions locally so the chosen order shows at once; a pull (which only runs with an empty queue) replaces them with Google's.

**Tech Stack:** existing: TypeScript, Preact, idb, SortableJS, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-17-subtasks-design.md` (builds on `docs/superpowers/specs/2026-11-17-todo-pwa-design.md`). Read `CLAUDE.md` first.

## Global Constraints

- Only `src/google/` talks to Google; `src/ui/` holds no logic worth testing.
- Every edit is one `store.commit` with a function that reads the latest state (see `src/store/edits.ts`).
- Every replay step commits its local effects in one commit built from the latest state (see `src/sync/push.ts`).
- No new dependencies.
- Subtasks are one level deep. A step is never shown on the board as a card, never in Today, and has no planned date in the UI.
- UI copy, exactly: field placeholder `Add a step`; delete button accessible name `Delete step “<title>”`; drag handle accessible name `Reorder “<title>”`; card count rendered as `<done>/<total>` with accessible name `<done> of <total> steps done`.
- UK English, plain wording. `npm run check` passes with no lint warnings for every commit.

## Review Focus

1. **Typing several steps quickly.** Each Enter adds in order, even while earlier adds are still committing. Test in Task 2.
2. **A step added and then deleted (or reordered and deleted) before sync.** Nothing reaches Google. Test in Task 3.
3. **Reordering a step to where it already is** (Alt+Up on the first step, or a drag dropped in place). Nothing is queued. Test in Task 2.
4. **A step's parent deleted on another device while a reorder or add is waiting.** The step is dropped with the usual "deleted elsewhere" notice, not an error that blocks sync. Test in Task 3.
5. **Renaming a step to blank.** The step keeps its old name; nothing is queued. Covered by `editTask`'s existing rule; checked by hand in Task 4.

### Task 2: Store — add and reorder steps, step counts

**Files:**
- Create: `src/domain/subtasks.ts`, `src/domain/subtasks.test.ts`
- Modify: `src/store/db.ts` (Op union, `renameChange`), `src/store/edits.ts`, `src/domain/board.ts` (`Card`, `buildBoard`)
- Test: `src/store/edits.test.ts`, `src/domain/board.test.ts`

**Interfaces:**
- Consumes: `reorderTask` semantics from Task 1 (not called here).
- Produces:
  - `Op` gains `{ kind: 'reorder'; listId: string; taskId: string; parent: string; previous: string | null }`.
  - `src/domain/subtasks.ts`: `subtasksOf(tasks: readonly Task[], parentId: string): Task[]` (sorted by `position` compared as `BigInt` when both are digit strings, else as strings, then by `id`); `renumber(orderedIds: readonly string[]): Record<string, string>` (IDs to 20-digit zero-padded positions `0…n-1`).
  - `Card` gains `steps: { done: number; total: number } | null` (null when the task has no subtasks), filled by `buildBoard`.
  - `addSubtask(store: Store, parentId: string, title: string, now: string): Promise<string>` — trims, throws on blank, throws if the parent is itself a subtask; new local task (`local-…` ID, parent's `listId`, `parent` set, no board entry), siblings plus the new one renumbered in one commit, queues `{ kind: 'create', listId, tempId, task: { title, parent } }`. Resolves `parentId` through `resolveId`.
  - `reorderSubtask(store: Store, taskId: string, previousId: string | null, now: string): Promise<void>` — resolves both IDs; throws if the task is not a subtask or `previousId` is not a sibling; returns `{}` (nothing queued) when the order would not change; otherwise renumbers the parent's subtasks to the new order and queues the `reorder` op.
  - `renameChange(s, fromId, toId)` also rewrites, in queued ops, a create's `task.parent`, and a reorder's `parent` and `previous`, that equal `fromId`.

### Task 3: Sync — replay reorders, safe step creates

**Files:**
- Modify: `src/sync/push.ts`
- Test: `src/sync/push.test.ts`; the pull round-trip test goes in `src/sync/pull.test.ts`

**Interfaces:**
- Consumes: `reorderTask` (Task 1); `Op` `reorder`, `addSubtask`, `reorderSubtask`, `renameChange` (Task 2).
- Produces: replay handling of `reorder`, nothing new for other modules.

Rules:
- `reorder` → `google.reorderTask(listId, taskId, parent, previous)`, then `settle` as `move` does (Google's result only replaces the local copy when no later op targets the task).
- On `NotFoundError` from `reorderTask`: `getTask` the step. Missing → `dropDeleted` (usual notice). Present → retry once with `previous` set to the nearest earlier sibling, in the local order, that `getTask` still finds, or `null`. If the parent itself is gone, the step is gone with it, so the first branch covers it.
- Create adoption (`createInGoogle`) matches `t.parent === (op.task.parent ?? null)` instead of `t.parent === null`.
- `dropUnsentCreates`: an unsent create (no `attemptedAt`) is also doomed when any queued `delete` targets its `task.parent`. Every op whose task is doomed is dequeued; the parent's own delete stays unless the parent is itself an unsent create.

test('a reorder replays with the right parent and previous after the parent was renamed', ...);
test("Google's order replaces the local one after a pull", ...); // pull.ts round trip
test('a reorder after a sibling deleted elsewhere lands after the nearest earlier sibling', ...);
test('a reorder of a step deleted elsewhere is dropped with a notice', ...);
test('a step whose parent was deleted elsewhere is dropped with a notice, and sync carries on', ...);
test('deleting a task drops its unsent step creates without calling Google', ...);
