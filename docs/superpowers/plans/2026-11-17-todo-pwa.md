# Todo PWA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Preact PWA over Google Tasks with a merged five-column kanban board, a Today view, offline editing, and board metadata stored in the Drive `appDataFolder`.

**Architecture:** Google Tasks stays the source of truth for task content. The app mirrors lists, tasks and board entries in IndexedDB, applies edits locally at once, and queues writes that replay in order when online. A sync cycle is: replay the queue; if it empties, pull every list in full; then read `board.json`, merge per entry, reconcile against the pulled tasks, and write it back if it changed.

**Tech Stack:** TypeScript (strict), Preact, Vite, vite-plugin-pwa (Workbox `generateSW`), Biome, Vitest, `idb`, `fake-indexeddb` (tests), SortableJS (drag and drop, touch), Google Identity Services token client. Node 24.

**Spec:** `docs/superpowers/specs/2026-11-17-todo-pwa-design.md`

## Global Constraints

- Scopes: `https://www.googleapis.com/auth/tasks` and `https://www.googleapis.com/auth/drive.appdata` only.
- Only `src/google/` talks to Google. `src/ui/` never calls Google.
- Columns, in order: `Backlog`, `Next`, `Doing`, `Waiting`, `Done`. Defined in code, no settings UI.
- `board.json` holds task IDs and board metadata only. Never a task title or notes.
- No secrets in the repo. The OAuth client ID is public and lives in `src/config.ts`.
- Due dates are calendar dates (`YYYY-MM-DD`). Google sends them as midnight UTC; take the date part, never convert through local time. "Today" is the device's local date.
- Done shows tasks completed in the last 7 days.
- Completing a task clears its pin. Quick add from Today also pins. Quick add lands at the bottom of Backlog in the last used list.
- Runtime dependencies: `preact`, `idb`, `sortablejs` only. Any other needs a stated reason in the commit message.
- Tests only where a rule can be wrong. No snapshots, no render-only tests, no "mock was called" tests.
- UK English, plain wording, in UI copy, docs and comments. Comments explain why, never narrate.
- Definition of done for every task: `npm run check` (typecheck, lint, test) passes.

## Review Focus

1. **Reordering while the board is filtered.** Hidden cards from other lists sit between visible ones. Dropping a card must place it right after the visible card it was dropped under and must not reorder hidden cards, even when the drop forces a rebalance. Test in Task 4.
2. **A pull that fails partway** (one list errors, network drops). Nothing is written and no board entry is pruned; otherwise a flaky connection deletes everyone's columns. Test in Task 8.
3. **A list with more than 100 tasks.** The Tasks API pages at 100. A missed page looks like deleted tasks and gets them pruned. Test in Task 9.
4. **Token expiry halfway through replaying the queue.** Replay stops, the failed op and everything after it stay queued in order, status becomes sign-in needed. Test in Task 7.
5. **`board.json` missing, empty, or malformed** (new device, hand-edited file, older schema). The app treats it as empty or skips bad entries and carries on; it never crashes or writes garbage back. Test in Task 3.

### Task 2: Rank insertion and rebalancing

**Files:**
- Create: `src/domain/rank.ts`
- Test: `src/domain/rank.test.ts`

**Interfaces:**
- Produces:
  - `export const RANK_STEP = 1024;`
  - `appendRank(ranks: readonly number[]): number` — `max + RANK_STEP`, or `RANK_STEP` when empty.
  - `placeCard(ranks: readonly number[], index: number): { rank: number; rebalanced: number[] | null }` — `ranks` is the column sorted ascending without the moved card; `index` is where it goes (0 = top, `ranks.length` = bottom). Normally the midpoint of the neighbours (top: `first - RANK_STEP`; bottom: `appendRank`). When the gap between neighbours is below `1e-6`, return `rebalanced` = new ranks for the existing cards in the same order, spaced `RANK_STEP` apart from `RANK_STEP`, and `rank` placed at the right slot within that new spacing.

- [ ] **Step 1: Write the failing tests**

```ts
test('places between neighbours', () => {
  expect(placeCard([1024, 2048], 1)).toEqual({ rank: 1536, rebalanced: null });
});
test('places above the top and below the bottom', () => {
  expect(placeCard([1024, 2048], 0).rank).toBeLessThan(1024);
  expect(placeCard([1024, 2048], 2).rank).toBeGreaterThan(2048);
  expect(placeCard([], 0)).toEqual({ rank: RANK_STEP, rebalanced: null });
});
test('repeated inserts at the same slot eventually rebalance and keep order', () => {
  let ranks = [1024, 2048];
  let inserted: number[] = [];
  let sawRebalance = false;
  for (let i = 0; i < 80; i++) {
    const { rank, rebalanced } = placeCard(ranks, 1);
    if (rebalanced) { sawRebalance = true; ranks = rebalanced; }
    ranks = [...ranks.slice(0, 1), rank, ...ranks.slice(1)];
    inserted = ranks;
  }
  expect(sawRebalance).toBe(true);
  expect([...inserted].sort((a, b) => a - b)).toEqual(inserted);
  expect(new Set(inserted).size).toBe(inserted.length);
});
```

### Task 3: Board entries — parse, merge, reconcile

**Files:**
- Create: `src/domain/board.ts`
- Test: `src/domain/board.test.ts`

**Interfaces:**
- Consumes: types (Task 1), `appendRank` (Task 2).
- Produces:
  - `parseBoardFile(raw: string | null): BoardEntries` — `null`, empty, invalid JSON, wrong `version` → `{}`. Entries with an unknown column, non-finite rank, non-boolean `pinned`, `openColumn` of `Done` or unknown, or missing `updatedAt` are skipped; valid ones kept.
  - `serialiseBoard(entries: BoardEntries): string` — `{ version: 1, entries }`.
  - `mergeEntries(local: BoardEntries, remote: BoardEntries): BoardEntries` — union by task ID; on both sides, newer `updatedAt` wins, tie keeps `remote`.
  - `completeEntry(entry: BoardEntry, now: string): BoardEntry` — column `Done`, `openColumn` = previous column (unchanged if already Done), `pinned: false`, `updatedAt: now`.
  - `reopenEntry(entry: BoardEntry, entries: BoardEntries, now: string): BoardEntry` — column = `entry.openColumn`, rank = `appendRank` of that column, `updatedAt: now`.
  - `reconcile(tasks: Task[], lists: TaskList[], entries: BoardEntries, now: string): BoardEntries` — only for the result of a pull that completed in full. Rules, all over top-level tasks (`parent === null`):
    - task with no entry → bottom of Backlog (`Done` if already completed), in Google order: lists in `lists` order, then `position` ascending. This also covers first run.
    - completed task whose entry is not `Done` → `completeEntry`.
    - open task whose entry is `Done` → `reopenEntry`.
    - entry with no matching task → removed.
    - untouched entries keep their `updatedAt`.

**Files:**

**Interfaces:**
- Consumes: `GoogleApi`, errors (Task 5); `Store`, `Op` (Task 6).
- Produces: `replay(google: GoogleApi, store: Store): Promise<'done' | 'offline' | 'auth' | 'error'>`. Ops run in `seq` order, one at a time:
  - `create` → `insertTask`; then `store.renameTask(tempId, real.id)` so later ops, the entry and the mirror use the real ID; `putTask(real)`.
  - `patch` → `getTask` first. For each field in `set`: if the remote value differs from `base` and from `set`, someone else changed it; leave it, and add a notice naming the task and the local value that was not applied (no silent loss). **Files:**

**Interfaces:**
- Consumes: Tasks 3, 5, 6, 7.
- Produces (`pull.ts`):
  - `pull(google, store, now: Date): Promise<void>` — fetch all lists, then every list's tasks with `completedSince` = now − 7 days (ISO). All or nothing: any error propagates and nothing is written. On success: `replaceRemote`, then `syncBoard`.
  - `syncBoard(google, store, now: Date): Promise<void>` — up to 3 attempts: `readBoard` → `parseBoardFile` → `mergeEntries(local, remote)` → `reconcile(tasks, lists, merged, nowIso)` → if `serialiseBoard(result) !== serialiseBoard(remote)` then `writeBoard(raw, version)`; `'conflict'` → retry from the read.     | { kind: 'idle' } | { kind: 'syncing' } | { kind: 'synced'; at: string }
